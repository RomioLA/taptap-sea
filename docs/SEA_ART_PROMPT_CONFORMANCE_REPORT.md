## 2. 当前接入实际做了什么

截图中的太阳、云、飞鸟、船、鱼和棕榈岛来自原 `Ocean.Draw` 的 NanoVG 绘图函数，并非本轮生成的新图片。本轮复用这些函数，鱼配色也取自原 Config.fish；没有创建另一套素材目录。

Main → FusedScene → Bootstrap → SeaRuntime / SeaDraw。Main 只保留 require、Start 和 Stop。SeaDraw 将真实世界实体投影到屏幕，再调用原船鱼岛造型；不会为了装饰画面另外生成假鱼，也不会通过绘图改变鱼的 AI 或实体位置。

原 HUD 文件与 State 文件保持原始字节。SceneState 将原标题和底部左右/暂停/重置按钮接到真实船和世界；新增“海上调试”，默认收起面板。浮物、临时诱鱼对象、目标标记和调试图形沿用 A 的实现。

天空、太阳、鸟和海浪目前作为屏幕背景绘制；船、真实鱼、岛和浮物使用世界坐标。背景飞鸟不承担捕鱼或生态实体职责，太阳也没有新增昼夜玩法。

## 4. 本次复核发现的实际偏差与原型简化

### 4.1 全屏45m，不等于当前有效海域45m

[Movement.SetViewport](C:/codex/taptap-sea/scripts/Ocean/Movement.lua:144) 以整个屏幕高度建立45m投影。[SeaDraw](C:/codex/taptap-sea/scripts/Ocean/SeaDraw.lua:226) 又从屏幕高度32%处开始裁剪世界实体，以上为天空背景；[FusedScene](C:/codex/taptap-sea/scripts/Ocean/FusedScene.lua:15) 也阻止天空点击航行。

因此，扣除天空、尚未扣除 HUD 遮挡的可显示水域高度为：

`45 × (1 − 0.32) = 30.6m`。

16:9下仍横跨80m，但真实水中实体只能显示在约80×30.6m的矩形内。上方14.4m投影范围被天空裁剪；对象并未从世界删除，可能仍在运行或可被查询。即使Debug/透视判断对象可见，位于天空裁剪范围内也不会实际画出来。

**若45m指整个相机/等价投影视口，当前参数符合；若45m指实际可操作、可显示实体的海域，当前仅有30.6m，不能认定符合后一个解释。** 我前一轮对此说明不够精确。原测试分别验证“投影45”和“海面以下裁剪”，没有验证两者叠加后的有效海域是否仍满足45m，这是覆盖缺口；原补充未明确扣除天空后的口径，本报告不直接把这一点判成数值违规。

后续应明确45m指全屏投影还是可操作海域。若要求海域本身45m，应调整投影/布局，并同步复核宽度、dead-zone、输入逆变换和UI；不应在本次报告中直接改数值来掩盖差异。

### 4.2 岛屿画法与碰撞形状不对应

[Draw.WorldIsland](C:/codex/taptap-sea/scripts/Ocean/Draw.lua:375) 沿用扁平侧视棕榈岛，按 entity.radius 缩放横向宽度；World 的阻挡仍是世界平面内的圆。

例如半径12m的岛：碰撞圆上下各延伸12m；原沙滩主体椭圆半高约为 `33/149×12 ≈ 2.66m`。这两者不是同一个轮廓。玩家可能在图上看起来仍是水面的位置就被岛阻挡，不能称为视觉与碰撞完整一致。

Debug 的边界圆可帮助核对，但默认隐藏。原提示明文要求“岛阻挡船”，没有规定碰撞必须逐点贴合插画，因此逻辑要求满足，不能把造型偏差单独算成明确违规。不过两者贴合仍需处理和实机验证，才能减少看似空水面却被阻挡的体验。建议保留原棕榈树/沙滩细节，同时让可见岛屿占地与碰撞形状采用一致的投影规则。

### 4.3 船的四向转向目前只有简化的画面表达

[Draw.WorldBoat](C:/codex/taptap-sea/scripts/Ocean/Draw.lua:315) 保持侧视船直立，只按水平分量左右镜像，不按完整世界 rotation 旋转船图。真实移动仍有180°/s转向限制，但向上/向下航行时船图没有对应的独立朝向。

原任务允许临时美术，没有强制八方向船动画，所以这是原型表现简化。操作时能否看清真实朝向尚待验证；可考虑方向提示或更多朝向造型，不必牺牲原船细节。

### 4.4 展示图不等于正式出生画面

上次展示的 PNG 是离线执行 SeaDraw.Scene 的绘图捕获，不是 Maker 原生截图；它没有渲染原 HUD。为了展示复用的岛鱼形状，测试额外建立了近处岛和两条鱼；reveal图开启Debug显示。正式地图和生成配置没有因此改变。

测试明确使用 initializeRegions=false，不运行普通区域初始生成，手工放置岛(-14,-12)、小鱼(-8,-8)、大鱼(8,-14)。其中小鱼距船约11.3m，大鱼约16.1m；这些测试位置不能用来证明普通区域生成的15/30/200m限制。它们是直接构造的绘图测试实体，不是正式生态出生结果。

正式固定岛为(35,25)、半径12m，以及(-80,90)、半径20m；船初始(0,0)。1920×1080下第一座岛中心约投到(1800,48)，在海域裁剪线y≈345.6以上，第二座岛又在镜头外。因此实际默认首屏不会出现展示图左下那座棕榈岛；玩家航行到相应位置后才可能看到正式岛。这个区别需要明示，不能把离线展示布局说成真实默认画面。

正式初始状态默认隐藏水下鱼，而且金枪鱼普通生成必须同时满足距当前船至少30m、距当天出发点至少200m。不能承诺一开始就出现展示图中的橙色金枪鱼，或小岛固定在图中左下位置。鱼隐藏/初始无金枪鱼符合玩法规则；把展示fixture视为正式分布则会产生误解。

## 5. 为什么船鱼比原截图小，哪些值不是用户定稿

原演示场景按屏幕比例摆放和缩放装饰船鱼；接入后使用真实世界位置和世界绘制尺寸。当前采用此前代理设置的暂定视觉尺寸，并非原任务明确指定的最终尺寸：

| 字段 | 当前值 | 1920×1080、全屏45m投影时的名义尺寸 |
|---|---:|---:|
| Config.visual.shipLength | 5m | 船图宽约120px |
| Config.visual.shipWidth | 2.4m | 原侧视船图高度缩放依据，约57.6px |
| FishData.sardine.renderLength | 1.8m | 约43.2px |
| FishData.tuna.renderLength | 3.8m | 约91.2px |

这些值在此前原型中已存在，本次融合没有重新决定它们。保留画法不意味着保持原演示图的像素大小。特别是 shipWidth 在适配器中用于侧视造型高度，不是完整船体几何定义。

原橙色/浅绿配色来自既有 Config.fish，本次按用户美术要求复用。视觉尺寸、船碰撞半径、测试岛/浮物的位置尺寸等代理补足值仍应按来源区分，不能因为所在表有整体 V1_IMPLEMENTATION_VALUE 标记，就认为每个视觉字段都已由用户定稿。后续调参应继续留在 Config/FishData。

局部生态目标20/4也不表示屏幕同时显示20/4。120m半径的活动区域远大于当前视野，且鱼默认隐藏。此前生成/投影统计不能替代融合裁剪后长期屏幕可见数量的测量；本次没有测量原生画面的平均可见数量。

## 8. 后续需要收敛的事项
