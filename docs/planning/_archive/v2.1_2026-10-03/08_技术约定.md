# 技术约定

本页补齐实现约束与程序验收要点，沿用现有工程架构，不新增第二套世界、玩家状态或时钟。已定玩法见对应系统与数值页；候选方案不构成改代码或新增数据字段的授权。

## 现有职责边界

下列架构来自最新工程通知。本机尚未同步架构说明和字段Schema，暂不声称已核对最新代码。后续按正式约定和实际代码落实这些职责；如确需调整边界，先说明原因、影响和最小方案并等待确认。

| 模块 | 职责与接入要求 | 边界 |
|---|---|---|
| Main | Maker生命周期、场景接线 | 不在入口另建玩法状态或第二套更新流程 |
| Game/Game | 整局更新与暂停同步 | 整局更新经既有Game调度 |
| Game/World | Entity注册、生命周期、System调度 | 海洋对象复用共享注册表，不建立第二套世界 |
| EntityFactory、StateMachine、EntityStateSystem | 实体创建、共享FSM和System更新 | 鱼行为沿用共享体系，具体生物内容不能硬塞进通用框架 |
| Ocean | 船鱼行为、生成、碰撞、查询、海洋绘制 | 不复制玩家状态和交易、时钟逻辑 |
| Gameplay | 玩家状态、体力、背包、交易、升级、昼夜与保存 | 体力属于玩家而非船；同一状态由现有模块统一维护 |
| Integration | Scene负责场景装配；Bridge将整局更新委托Game，并协调既有跨模块事务 | 各模块维护所属状态，确保一次动作的体力、物品与世界结果一致；不在Bridge另建世界、玩家状态或时钟 |
| 根data与GeneratedData | items.lua、fish.lua为内容数据来源，生成运行时副本 | 遵循DATA_SCHEMA；新增字段先确认，不把生成副本与根数据作为两份独立源维护 |

项目正式本地完整版为C:/codex/taptap-sea；taptap-sea-push是独立分批交付目录。通知中的远端提交2569cd4仅含AGENTS和架构文档，不能据此推断本地程序未接入，或声称本地程序已经远端交付。

## 实体、模拟与可见性

| 约定 | 实现要求 | 验收重点 |
|---|---|---|
| 对象类型与生命周期 | 支持固定、动态、临时对象；固定地点跨日保持，普通鱼按新日重建，临时投放物到期或换日清理 | 不因鱼刷新重建固定宝藏／事件进度；同日回来保持鱼状态 |
| 实体信息 | 每个实体具备唯一标识、类型、位置、方向／旋转、行为状态、激活／冻结信息 | 这些是功能信息要求；具体字段名按既有Schema映射，不直接新增ID、type、active等字段 |
| 鱼的实体粒度 | 一条可捕获鱼对应一个独立实体，不用FishGroup加count代替 | 捕食或捕获移除实际目标实体，其余鱼继续按各自状态运行 |
| 可见性与资格分离 | 水下隐藏不停止范围内模拟，也不取消捕鱼／交互资格；远距冻结按既定120／150米阈值处理 | 透镜只改变显示，不改变鱼AI、刷新、感知或交互资格 |
| 碰撞与交互 | 岛屿为实体障碍；木桶等普通漂浮物不阻挡船，但使用trigger／overlap提供交互 | 穿过漂浮物不撞停，不影响靠近后的交互检测 |
| 坐标与镜头 | 世界距离统一以米表示，镜头为正交跟随并使用既定死区和平滑 | 不再另外定义“视口宽100单位”；45米可视高度与HUD占用区域的实际口径需接入时核对 |

## 鱼的状态机

| 对象 | 状态范围 | 约束 |
|---|---|---|
| Sardine | Wander、Attracted、Flee、Avoid | 独立配置小鱼移动与感知数据，不增加Search状态 |
| Tuna | Wander、Attracted、Chase、Avoid | 独立配置大鱼移动与感知数据，不增加Search状态 |
| 共同优先级 | 障碍／边界 > 危险／追猎 > 吸引 > Wander | 由既有共享FSM／System组织，不能为鱼另建全局更新骨架 |
| 游荡与逃跑 | 游荡每2～4秒随机改向；小鱼逃跑每0.4秒允许±25°偏转 | 偏转后仍须总体远离危险，不机械直线逃跑，也不能偏回危险方向 |
| 目标失去与捕食 | Tuna失去猎物2秒后回Wander；1.5米接触捕食会移除Sardine实体 | 捕食间隔、饱食等未定边界仍待Q-008，不自行扩展规则 |
| 区域生成 | 活跃模拟区域以约20条小鱼／4条大鱼为平衡目标，按区域或群聚组织 | 不是全地图240／48，也不实时强制补满；离船和离出发点约束见数值页 |

## 海面信号接入

从现有鱼的位置、活跃状态和FSM派生海面提示，由Ocean维护提示状态，绘制层读取。复用Game的更新与暂停，不另建世界、鱼状态或时钟。0.25秒是状态检查轮询，捕获／被吃等失效事件需立即撤掉对应海鸟；暂停时巡游、水花生成与寿命计时同步停止。不得用定时装饰海鸟冒充功能信号。

海鸟关联真实活跃且未被捕获的小鱼；持续核对巡游提示区域中的有效投饵点与关联鱼距离不超过18米，不能只在首次生成时核对。8～10米中心偏移加3米巡游半径，在静态几何上最远13米；运动、检查间隔和投放时机仍须验证，且投饵需满足船12米限制。范围成立只说明诱饵可被感知，危险／逃跑优先级不变。鱼离开或冻结后不保留失真提示。大鱼水花从真实经过位置生成，按普通／Chase状态取间隔，用短尾迹表现方向，不用于直接暴露持续精确位置。

## 物品数据与跨模块事务

| 项目 | 当前约定 | 实现限制 |
|---|---|---|
| 基础物品标识 | apple、bait、sardine、tuna | 物品表中的中文小鱼／大鱼分别对应sardine／tuna；字段和加载方式按现有Schema |
| 物品分类 | fish、food、bait、treasure、misc | 分类用于物品管理，不直接驱动鱼AI；小鱼和大鱼的参数完全独立 |
| 生态效果 | ATTRACT_SMALL_FISH、ATTRACT_BIG_FISH、NONE | 苹果和鱼饵吸引小鱼，小鱼投放吸引大鱼，大鱼投放无生态效果；不因分类相同而复用错误效果，不任意扩增标签 |
| 统一投放 | 沿用统一WorldDrop职责，世界接受后才正式移除Inventory物品 | 不要求新增同名模块；失败或超距保留物品，不产生重复投放 |
| 捕鱼结算 | 确认约0.5秒后落水查询最近有效鱼并锁定0／1条；锁鱼退出普通AI，禁止被吃及重复捕获；总动作4秒 | 完整捕鱼／空网均40且只结算一次；结果按锁定值，不能结束时重查。扣费时点、取消及满舱边界见Q-002／Q-003 |
| 木桶多阶段事件 | 同一固定对象维护三阶段进度和一次性领奖状态；跨日保留、新周目重置，按日结保存 | 阶段推进与玩家反馈、物品奖励分别处理；第二次检查无物品奖励，反馈按剧情页执行。约4秒操作与暂停、中断、满舱事务见Q-014。先确认现有契约和Schema，不直接新增字段 |
| 成长升级 | Gameplay统一支付与保存等级，Ocean执行真实速度变化 | 船速等级与实际速度保持一致，不在交易模块复制移动逻辑；体力升级按上限差值增加当前值 |
| 交易失败 | 购买、出售和升级需保持金钱、物品、库存、等级一致 | 售罄不扣钱，失败不能只改变事务的一部分 |
| 配置集中 | 初始物品、升级价格、船鱼参数从对应数据配置读取 | 不在多个模块复制一套常量；修改数值记录批准来源，新增字段先确认 |

## 暂停、存档与新周目

| 项目 | 技术约定 | 验收重点 |
|---|---|---|
| 多原因暂停 | 使用统一pause reason，通过现有Game同步时钟与海洋模拟 | 多个暂停原因并存时，关闭一个界面不能错误恢复全部世界 |
| 暂停范围 | 港口、特殊事件、背包、老人对话暂停；船、鱼AI、投放寿命、临时揭示倒计时同步停止 | 捕鱼本身不请求暂停；捕鱼期间打开其它暂停界面的权限待Q-002 |
| 日结保存 | 每日结算后的唯一正常自动保存；World新日接口处理鱼刷新与临时对象清理 | 保存失败不能重复加天、重扣费用或留下玩家与海洋不一致的状态 |
| 保存内容 | 玩家与长期周目状态、背包、升级、地点识别、宝藏、剧情、老人状态；正常日结保存结算后的次日体力及当时动态上限 | 日期和状态对应同一次日结；不保存日中临时进度、普通鱼精确位置或逐实体FSM；具体字段对照Schema，不自行新增 |
| 新周目 | 重置本轮游戏状态，不做knowledge points或永久地图识别 | 玩家现实记忆是成长来源，不能新增隐藏捕获倍率 |
| 正式重开与旧存档 | 旧报告曾记录NewRun后旧云档直到下次日结才覆盖 | 同步后核对重开后立即退出／重进是否回到旧周目，不把Debug重置当正式重开完成 |
