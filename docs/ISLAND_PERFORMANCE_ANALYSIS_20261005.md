# 小岛入画卡顿专项分析

日期：2026-10-05；Issue：C1-PERF-09，继续开放。

当前已完成代码优化：岛内保守剔除、静态世界几何缓存、描边流式生成和同步投影参数复用，内容数量不变。53／53套圈1回归通过；完整可见代表岛算法CPU约减少47%、临时分配约减少60%。实机FPS仍待用户沿原路线验收，完整交付证据见末尾。

用户补充了出航后世界开始运动、小岛进入画面显著卡顿。代码和调用／分配证据与这一触发条件吻合：小岛外观简单，但实际描边链路细碎；只要部分入画，岛内全部组件先进入生成，再逐段裁剪。**先前分析阶段**完成了分析和诊断脚本，当时没有修改正式游戏代码或数量配置；其后的小岛优化实施与当前验证状态见下文。

## 确认的链路

入口是 `scripts/Ocean/SeaViewArt.lua` 的 `Island`，经 `SeaDraw`、`SeaPresentation` 调用。两层岸线各48条原始边；每条边进入 `ProjectedGeometry.StrokeWorldLine`，先做世界裁剪，再按世界距离／屏幕距离细分，投影为屏幕四边形带并裁剪地平线，最后填充。它并不是两次简单的原生描边。

泡沫通过 `drawShoreFoam` 生成36组动态弧线；采样时32组超过当前强度阈值，每组4段，共128次描边。强度阈值和数量来自现有配置，没有修改。岸线、山体和树的世界几何也会在每次绘制重新构造。

`SeaPresentation.State` 已能拒绝完全屏外的整岛；问题在岛内粒度。一小部分入画就进入完整 `Island` 回调，余下组件仍逐一生成和检查。不能把诊断脚本强制绘制完全屏外岛的结果误认为正式Scene仍绘制该岛。

主要结构性负担在岸线与泡沫：它们占224／246次填充提交，并制造大量临时顶点、投影、裁剪工作。4棵树不是首要优化对象；填充提交比例也不能直接等同CPU或GPU耗时比例。

## 计时校正与限制

最小等待实验：Lua `os.clock()`在Python等待0.25秒时增加约0.25秒，而进程CPU增加约0。因此此前以 `luaCpuMs` 命名的值实际是离线经过时间，已更正文档；旧JSON保留，不作为CPU数据使用。

新脚本绑定Python `time.process_time` 测进程CPU、`perf_counter` 测经过时间。每种组件使用相邻的原样／临时跳过／恢复原样对照，只作用于隔离进程。采样仍有较大波动，出现负增量或增量超过前段全岛中位数，不能发布可靠CPU百分比。插桩耗时含额外包装和计数开销，不能与未插桩全岛耗时相加。关闭共享轮廓函数还可能同时影响山体的关联描边，不能把这一增量全部归为岸线。

本轮稳定结论依据源码、调用数与停止GC的单帧分配。尚未测原生NanoVG曲面细分、GPU、驱动、真实UI或实机FPS，因此小岛是有明确证据的重点，尚不能宣布已解释所有掉帧。

## 先前分析阶段提出的优化建议

1. 提前做岛内保守剔除：岸线段、泡沫弧、山体、树各用完整包围体判断；保留部分可见内容和地平线附近的精细裁剪。比只判断中心点安全。
2. 改善连续岸线链路：复用相邻边端点和采样工作区，按可见连续片段生成；再减少细碎提交。批处理需保留颜色、透明度、覆盖顺序和接缝，不能简单把所有半透明路径合并成一次填充。
3. 缓存静态世界几何：岸线、山体、树按实体位置／半径／相关配置失效；相机变化仍重新投影，泡沫按时间更新。优先减少热点中的临时表，单缓存96个岸线原始点不会独自解决问题。
4. 各补丁单独验证：正常视口、部分入画、完全屏外、地平线穿越、小岛；核对内容数量、颜色、轮廓、线宽与顺序，跑相关回归后再由用户同场景验收。

不降低泡沫组数、岸线段数、岛屿／树数量或海面密度。当前配置保留，结局文案不在本轮范围。

## 后续优化实施记录

在先前分析阶段之后，已对小岛绘制链路实施优化：

- `ProjectedGeometry.StrokeWorldLine` 对贴水且严格位于地平线近侧的线，按原采样点顺序流式生成相同四边形带，省去样本数组、顶点临时表、不必要的可见性判断和完整裁剪工作。地平线附近的线，以及山体和树的抬高描边，继续走原算法。
- 新增 `Geometry.WorldBoundsVisible`，用完整 AABB 对现有世界视域平面做保守拒绝；`SeaViewArt` 用它先拒绝完全屏外的岛面、山体、树和泡沫弧。
- 按实体弱键缓存静态世界几何，包括两圈岸线、山体和树；位置坐标、半径或段数变化时重建。跨帧只缓存这些世界几何。同步绘制时，`Projection.ProjectFunction` 复用本次绘制的投影参数；每次 `Island` 使用临时 frame 对象复用 `project`／`horizon` 函数，不把这些函数或参数跨帧缓存。每条泡沫弧复用颜色对象，泡沫数量及岸线、岛屿等内容密度不变。

**内容与配置：** 泡沫36组、岸线48段、波纹近／远间距12／6米、预算1800均保持不变；Config哈希仍与圈1一致：`0925987ACF914F3CFAED61EB7964260C5815371C0B5C3AA75F74450694CFE9C2`。半透明路径没有简单合并填充。
