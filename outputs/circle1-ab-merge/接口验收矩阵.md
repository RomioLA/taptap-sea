# 圈1 A/B 最终接口与验收矩阵

状态：B4 已交付，当前 C 工程已完成组合修复与离线回归。执行结果、源码冻结和未测边界见[合并复查与交付](合并复查与交付.md)。本矩阵保留合同及原生/真实云后续验收清单。

范围依据：当前 A 的 Ocean/World/Bootstrap/EntityStateSystem 实现、项目架构约定、圈1合并准备和 A3/B3 复查说明。代码装配由 B4 完成；最终检查必须针对 B4 冻结后的当前工作树，且先核对 B4 最终文件清单、哈希和 A 保护基线。

## 已确认规则与状态归属

- 木桶打捞的 4 秒期间，海洋模拟与 Gameplay 昼夜继续推进；对话或背包打开时暂停。
- 捕鱼已完成但尚未领取的鱼获必须保留；未完成的捕鱼动作可按既有日结规则取消。满舱处理须原子，固定木桶不得因捕鱼或领取失败被清除。
- 圈1沿用 B 的基础存档契约，并在新局建立时保存初始状态；日结保存、读档、失败重试或明确放弃本次保存后继续都要保留。
- 图鉴、成就和正式结局留待后续圈次；圈1不新增相应存档字段或自行补入正式结局。
- Gameplay 持有玩家资源、昼夜/保存、地点识别、捕鱼交易事务、待处理动作和奖励状态。Ocean Runtime 持有海洋实体、船移动、捕获锁和海洋模拟。Integration 只转发、装配和编排，不直接写实体或保存第二份跨帧玩法状态。

## A 侧接口合同

| 项目 | 当前接口与真实语义 | B 使用边界与验收重点 |
|---|---|---|
| 港口坐标与复位 | GetPortPosition() 返回 Config.ship.start 的坐标副本；ResetShipAtPort() 返回 true 或 false, reason。成功时只复用现有船、World 和 Movement，把船送回港口，并清导航目标、碰撞推力反馈、重锚相机。它不结算日子、不推进时间、不刷新鱼、不改暂停、透镜、信号、鱼或固定木桶。 | 正常返港仍须真实航行进入 Gameplay 的 10 米门禁，不能用 Reset 瞬移。强制返港、新日准备、读档/新局等被 B4 既有流程要求复位时才调用；空间阻塞或位置非法时必须保留船位置及原导航/推力状态并报告失败。 |
| 固定木桶凭证 | GetFixedBarrel() 返回只读快照：id/contentId/generation/position；坐标也是只读副本。CanInteractWithBarrel(id, generation) 只检查代次、当前确切注册实体、船位置和 5 米交互范围，返回 true 或 false, reason。它不启动动作、不收费、不暂停、不发奖励。World 重建会改变木桶 generation；仅刷新鱼或港口复位会保留当前木桶及其 generation。 | Gameplay 保存自己的动作阶段与幂等收据，调用时提交同一快照的 id/generation；超距、错 ID、错 generation、木桶失效都拒绝且不收取/重复奖励。20 米识别和 80 米轮廓绘制不是 5 米交互距离的替代。Generation 是进程内 World 凭证，不保存到云档。 |
| 捕鱼选择、锁定、移除与回滚 | selectFishingTarget(center, radius, filter) 使用配置的投网半径和船投网距离，返回最近可捕获鱼或 nil, reason；隐藏/冻结鱼仍可选，已锁鱼跳过。LockFishingTarget(id, ownerToken) 要求 table token，以对象身份认主；返回 true 或 false, reason。锁定会暂停该鱼的 FSM/移动，阻止捕食和重复选择，并立即撤销其海面信号。UnlockFishingTarget 对缺失/已解锁目标幂等成功；错误 owner 返回失败。RemoveFishingTarget(id, ownerToken) 对锁定目标要求精确 owner，成功才从 World 移除。SnapshotFishingTarget/RestoreFishingTarget 是同一事务内的失败回滚接口。 | Gameplay 为每次事务持有同一个 table token 和临时快照，Ocean 负责实体锁及注册表变化。删除或入舱失败时以快照恢复原鱼/行为并解锁；不能直接写 entity、byId 或实体数组。回滚只接受同一 Runtime World、同一 fishing generation、同一目标对象；快照/owner 不得存档或跨日/跨新局复用。成功捕获只发放一次；已完成未领取的鱼获不得随夜尽丢弃。 |
| 透镜 setter | SetScopeEnabled(enabled) 把持久水下视野状态设为 enabled == true，并返回修改后的状态；IsScopeEnabled() 回读当前状态。因此成功关闭时 setter 的返回值就是 false。非布尔 true 的输入也会安全关闭并返回 false。它不暂停或推进海洋。 | B4 要求关闭时必须把 false 视为期望状态，不按 setter 的真假值判定接受与否；调用后用 IsScopeEnabled() == desired 核实。透镜开关属于 Ocean，永久透镜宝物及其进度属于 Gameplay；关闭观察不扣除、不移除该宝物。对话/背包暂停与透镜状态相互独立。 |
| 可选只读绘制输入 | Bootstrap.Start 可选接收 getClock()、getFishingView()、isLocationRecognized(contentId)。每次 Render 读取 clock/view，并按顺序将 runtime, clock, fishingView, isLocationRecognized 传入 SeaDraw.Scene 的第 4–7 个位置。SeaDraw 只据 clock 显示夜色、据 fishingView 画捕鱼阶段、据识别查询决定已发现木桶外观；绘制不结算、收费、推进时间或保存识别状态。 | Gameplay 提供现有 clock 的只读读取、捕鱼视图快照与 IsRecognized 类只读查询；Ocean 不缓存第二份状态。每帧绘制前后玩家、存档、昼夜、海洋实体和动作阶段均不变；回调缺省或视图无效时仍可绘制普通海洋，不把缺少可选回调当成 Gameplay 状态。 |
| 指针消费与停止 | HandlePointer(physicalX, physicalY) 对有效海面点先调用可选 beforePointer(runtime, bootstrap)，再检查暂停、窗口/DPR、UI 命中及海面合法性。onSeaPointer(position, runtime, bootstrap) 只有精确返回 true 才消费：Bootstrap 随后不执行自己的 SetTarget 回退；回调仍可按动作需要调用 ClearMovementTarget。返回 false/nil 时 Bootstrap 设置点击点为正常航行目标。Mouse 与 Touch 共用此路径。Stop() 幂等取消本 Bootstrap 的事件订阅并释放自己的节点/绘图资源。 | 捕鱼/木桶点击由 B4 回调处理后返回 true，Ocean 不得再因同一次 click 设置点击点为导航目标；B 回调可以按动作合法清除既有导航目标。未处理的合法海面点击才由 Ocean 落为导航。暂停、UI 上点、非法点、停止后事件不能进入玩法回调或改变航行目标。验证鼠标、触摸、UI 命中和窗口尺寸/DPR 改变。 |
| 唯一 World、System 与时钟 | Ocean.World 继承 Game.World，共用实体集合、ID 索引及 scheduler。Runtime 初始化只向同一 World 注册 EntityStateSystem 与 SurfaceSignals 海洋子步 System。Game.World:AddSystem(system, cadence) 按 system 对象去重；同一 system 不可换 cadence。Ocean 子步时间不等同于 Gameplay 昼夜时钟。 | Gameplay 周期更新作为 frame System 加到同一 World；整局每帧只执行一次，海洋继续按自己的步长/帧上限更新。昼夜由 Gameplay 持有并只推进一次；Ocean 通过只读 callback 绘制，不新建或推进时钟。Integration 不额外直接调 Gameplay.Update 或再建 World。 |
| 当前 World 入口 | 组合中已有 Game:GetWorld()：它返回 self.runtime.world 的当前引用，并调用 World:AddSystem(self.gameplaySystem, "frame") 保证 GameplaySystem 已注册；重复调用会去重，所以这是有幂等注册副作用的读取，不是纯 getter。当前正式 NewRun 路径通过 ResetShipAtPort() 与 refreshOrdinaryFish() 保留 World；独立调用 Runtime:Reset() 才退休旧 World 并创建新 World。 | 初始化 Game 后再用 game:GetWorld() 读取/核对 World 身份。正常新局前后应为同一 World、System 数量不变；只有独立 Runtime:Reset() 生命周期回归才断言旧 World retired、新 World 被 getter 取回并注册 GameplaySystem。日结/新局不得缓存过期 fish/action 引用。不要推断未存在的 Runtime 字段。 |

## B4 冻结后的可执行检查

每项都在最终 B4 工作树上执行并记录实际调用链、断言结果和测试边界。正向与反向断言要同时保留；不把旧报告的数字、旧 D 盘快照或组合器结果当作本轮最终结果。

1. **文件与基线**：冻结 B4 最终同步/修改/新增文件、哈希及恢复快照；将 A 的 Ocean 全模块、EntityStateSystem 和 A1/A2/A3 测试与 a-protection.json 对照，任何授权差异逐项列出。运行最终工作树中的真实 A+B 玩家与装配入口，不能只运行旧 B 副本。被保护源码意外变化、最终文件不在清单内或只有旧来源测试通过均为失败。

2. **唯一 World / 系统 / 新日与新局**：
   - 初始化 Runtime、Game、Bridge 后，记录 game:GetWorld() 返回对象和 systems/systemCadences。重复读 getter 后 Gameplay frame System 只有一份；海洋两个 simulation System 各一份，且都挂在这同一 World。
   - 按真实 Gameplay 新日入口日结并进入新日：Ocean World 身份不换，普通鱼/临时物依规则刷新，木桶实体与 generation 保留，Gameplay 保存与识别进度按既有契约保留；重新取 World 不重复注册 System。
   - 按当前真实 NewRun 入口执行 ResetShipAtPort() + refreshOrdinaryFish()：前后 World 是同一对象，已注册 Systems 不增不减；新局识别清空，Gameplay 新局状态初始化并保存初始状态一次，旧鱼/动作凭证不再可用。不能为了让此检查通过而调用 Runtime:Reset()。
   - 将 Runtime:Reset() 作为独立的 World 生命周期回归：显式单独调用后，旧 World 的 retired 为 true，旧更新无效且不能再注册/生成实体；game:GetWorld() 返回新 World 并只注册一份 Gameplay System。此项不代表正式 NewRun 会重建 World。
   - 用大于海洋单步上限的一帧核对 Gameplay/clock 只更新一次，Ocean 可以分子步更新。暂停时同帧同步后船、鱼、临时寿命都停；恢复后继续。昼夜变化不得按 Ocean 子步数倍增。

3. **返港与复位**：从真实航行状态读取 GetPortPosition()，改动返回的坐标副本后再次读取仍应得到原港口锚点。正常返港从海上实际航行到 10 米门禁后结算，不得调用复位瞬移。强制返港/新日/读档/新局仅在 B4 既定流程中调用 ResetShipAtPort()；成功后仍是同一船、World、鱼、固定木桶、signal system、时间与暂停状态，旧 target/push 清除。用港口 blocker 和非法端点各走一次反例，需 false, reason 且船与 movement state 原样保留；重试不产生第二 World。

4. **木桶凭证与事务**：从 GetFixedBarrel() 保存 id/generation；在真实 5 米范围调用 CanInteractWithBarrel 应为 true，边界外、错 ID、旧 generation 分别拒绝且不产生费用/阶段/奖励。调用真实 4 秒木桶流程一次：动作期间 clock 与海洋都继续；完成恰好一次阶段奖励/资源变化，取消、失败和重复回调不二次收费/领奖；满舱时按已确认规则原子处理并保留固定木桶。打开对话/背包后同一更新入口须同步暂停 Gameplay 与 Ocean。

5. **透镜反向契约**：以真实 Runtime 连续执行 SetScopeEnabled(true)、SetScopeEnabled(false)；开启后的返回与回读均为 true，关闭后的返回与回读均为 false。重点把关闭场景执行到底：B4 将 false 识别为期望状态而成功停止观察，不误回滚并重新开启，也不扣除或移除 Gameplay 持有的永久透镜宝物。非布尔输入也不得打开透镜；若用拒绝写入的替身模拟 setter 未达到期望状态，B4 必须根据回读报告同步失败。

6. **捕获锁、删除和补偿**：通过真实投网选择一个目标，用新的 table owner 锁定；同 owner 重复锁可幂等，第二个 owner、无 owner 删除或捕食删除均失败。锁定中鱼不移动/更新/被吃/重选，且其表面提示消失。完成动作时只由 Gameplay 对目标做一次背包入账并调用 owner 删除。强制制造“删除失败”及“入账失败”两条路径：B4 通过同事务快照恢复同一鱼与 AI，使用原 owner 解锁，费用和奖励回滚；错误 owner、refresh 后旧 owner、Reset 后旧 snapshot 不得碰新鱼。夜尽时保留已经完成但未领取的鱼获；仅未完成阶段取消。

7. **可选只读绘制回调**：正常装配后分别有/无 getClock、getFishingView、isLocationRecognized callback 跑多帧 Render。比较前后玩家、clock、存档表、sea time/实体、动作阶段均未改变。识别查询只给已在显示范围的木桶外观使用：近距离 20 米识别规则、远处 80 米轮廓范围分别有效；超出可见范围不得因已识别而画出物体。坏/缺省 fishing view 不启捕鱼事务，夜色只读 clock phase。

8. **输入消费与暂停同步**：先用仅返回 true 的隔离 onSeaPointer 夹具并保留一个既有导航目标，验证 Bootstrap 不把 click 点另设为航行目标；再走 B4 的真实交互回调，允许其通过 ClearMovementTarget 清除旧目标，同时断言 Ocean 没有执行 click-to-move 回退。回调 false/nil 的合法海面点才由 Bootstrap 设置航行 target。覆盖按钮/输入框命中、暂停刚发生/刚解除、越窗/NaN/阻挡水域、DPR/窗口 resize、Bootstrap Stop 后迟到的 MouseButtonDown/TouchBegin/Update；无效/被 UI 消费/暂停/Stop 的路径不得触发玩法回调或移动船。多次 Start/Stop 后只存在当前一套事件订阅和一条更新链。

9. **日结、读档和新局保存**：使用最终 B4 的正式入口，检查日结保存、读档恢复、无档、保存失败重试/明确放弃后继续，以及新局建立时立即保存初始状态。模拟旧异步 load/save 回调在新局后返回并尝试应用本地状态，验证本地 run/session 校验拒绝旧回调覆盖当前本地状态。这个断言不证明远端同 key 写入按新旧顺序应用；SDK 超时/重试后的远端同 key 排序作为独立真实服务风险待验。保存内容继续沿用 B 基础 Schema；图鉴/成就/正式结局字段不存在于圈1新增存档。内存 Store 测试只能证明代码保存边界；真实云读写、跨启动恢复仍单独标记为未验收，不能由替身通过推断成功。

10. **公开 Runtime façade 兼容性**：正常构造 Bridge.New(realRuntime, options) 后，仅替换 bridge.runtime 为公开方法代理，对 world/ship/movement 等非方法字段读取报错；bridge.game.runtime 保持真实 Runtime。真实 NewRun/新日准备收据通过公开 GetFishingGeneration() 获取代次，不需读取 World。当前 Architecture 测试已通过这一路径；Game:GetWorld() 的 World 读取、GameplaySystem 去重及独立 Runtime:Reset() 生命周期由其余架构用例单独验证。此夹具只证明构造后 Bridge 的公开方法调用兼容，不声称任意 façade 可注入 Bridge.New，也不声称 A 有 Runtime:GetWorld()。原准备矩阵要求准备收据经 game:GetWorld() 的写法过度约束，现按实际所需语义修正。
