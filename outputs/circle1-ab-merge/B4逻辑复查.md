# B4逻辑复查

**结论：** 当前 C 的 B4 逻辑有两项可复现问题：夜尽与桶动作同刻完成时可能停滞，带边界拆分的单帧可能让海洋模拟超过帧预算。木桶动作的键盘输入锁定、背包/对话暂停和透镜关闭回读符合约定。公开 Runtime façade 的代码路径静态兼容，但接口矩阵要求的准备回执 World 身份动态检查未完成。

## 范围与证据

复查当前 `C:/codex/taptap-sea` 工作树的 `Gameplay`、`Integration`、`Game.Game`，按架构布局、B4 交付说明、A/B 复查说明和接口验收矩阵核对。与 `outputs/circle1-b4/pre-sync/current-c` 只读比较，未用 D 盘旧 B 源码替代当前 C 证据。B4 的回归 runner 和其他旧 runner 均未导入或执行。

独立复现以 Lua 5.4/Lupa 直接加载当前 C 的 `Gameplay.Loop`、`Gameplay.Circle1B2Barrel`、`Gameplay.GameClock`、`Game.Game` 和 `Ocean.SeaRuntime`；未调用测试套件。脚本及原始结果在 [b4-logic-evidence](b4-logic-evidence/)： [repro_b4_logic.py](b4-logic-evidence/repro_b4_logic.py)、[results.json](b4-logic-evidence/results.json)。没有改生产源码或测试。原生窗口和真实云未运行，不能据此推断通过。

## 已复现问题

### B4-1 夜尽与木桶完成并列时停在未完成状态，余帧可卡住更新

当前 [Loop.lua](../../scripts/Gameplay/Loop.lua#L131) 先按捕鱼/木桶剩余时长切片，再将切片限制到夜尽边界；边界限制发生在零切片恢复检查之后（约第131–162行）。`GameClock:Update` 以精确浮点比较决定耗尽（[GameClock.lua](../../scripts/Gameplay/GameClock.lua#L139)），木桶 `Advance` 用 `+1e-9` 判断已到时长，但随后 `AcceptCompletion` 又要求证据时长严格不少于4秒（[Circle1B2Barrel.lua](../../scripts/Gameplay/Circle1B2Barrel.lua#L129)、[Circle1B2Barrel.lua](../../scripts/Gameplay/Circle1B2Barrel.lua#L185)）。

Lua 5.4 复现把时钟置于夜尽前0.1秒、木桶动作置于完成前0.1秒，然后更新0.1秒：时钟 elapsed 到达 `nightSec`（60），但 `exhausted=false`；动作停在 `elapsed=3.9999999999999942`、`state=waiting`，未推进阶段且未扣体力。接着用含 `0.0000001` 秒余量的 `dt=0.1000001` 更新，Lua 指令保护在第20次触发；动作仍未完成，时钟未进入 forced return，Ocean 只推进了首段0.1秒。结果见 `exact_night_tie` 与 `night_tie_with_frame_remainder`。

这是由当前代码的时长容差不一致与切片无进展共同造成的功能问题：木桶候选完成被严格证据检查拒绝，时钟却已舍入到边界而未标记耗尽；下一循环的夜尽剩余被钳为0，正数 `remaining` 不会减少。用户确认的“恰好在夜尽完成则结算一次，未完成则免费取消”在该边界没有实现。可定位到 [Loop.lua](../../scripts/Gameplay/Loop.lua#L137)、[Loop.lua](../../scripts/Gameplay/Loop.lua#L143)、[Loop.lua](../../scripts/Gameplay/Loop.lua#L158)、[Circle1B2Barrel.lua](../../scripts/Gameplay/Circle1B2Barrel.lua#L132) 和 [Circle1B2Barrel.lua](../../scripts/Gameplay/Circle1B2Barrel.lua#L188)。

### B4-2 边界拆片后单帧海洋预算被重复套用

[Game.lua](../../scripts/Game/Game.lua#L47) 设定 `seaBudget = min(dt, maxFrameSec)`，但只有捕鱼 `splitCast` 路径按整帧预算比例分配（约第51–58行）；木桶路径把每个 `slice` 直接交给 `Runtime:Update`。B4 的 [Loop.lua](../../scripts/Gameplay/Loop.lua#L131) 会在木桶完成边界拆帧，而 Runtime 对每次调用分别应用0.25秒上限（[SeaRuntime.lua](../../scripts/Ocean/SeaRuntime.lua#L427)）。

复现中木桶剩余0.1秒、帧 `dt=0.5`：Loop 分成0.1秒和0.4秒两次 Ocean 更新，最终海洋时间增加0.35秒，超过 `Ocean.Config.world.maxFrameSec=0.25`；Gameplay 时钟增加0.5秒，动作正常完成。原始值在 `split_frame_budget`。B4 前同步版 Game 只在帧调度后调用一次 `Runtime:Update(dt, ...)`；当前对动作边界拆片后多次调用 Runtime，是这项回归的触发条件。长帧/动作边界时海洋相对整局时钟多模拟，违反单帧海洋预算。

## 已核对通过的逻辑

- 木桶最后一个普通0.1秒切片，键盘 `axisX=1` 持续按下时，船位仍为 `(64,25)`；木桶完成、阶段推进一次并扣40体力，同时 Gameplay 时钟与海洋时间各推进0.1秒（`final_0_1_frame`）。单个4秒帧也保持船位不变、结算一次，Gameplay 时钟推进4秒；Ocean 受既有0.25秒单帧上限限制，只推进0.25秒（`single_4_second_frame`）。因此正常切片顺序下，动作覆盖的最后普通 slice 仍处于 `IsMovementBlocked()`，未观察到动作最后一段提前恢复键盘输入。
- 木桶进行中打开背包或第7天纸条对话，入口均接受暂停；下一帧 Runtime.paused 为 true，Gameplay 时钟和 Ocean 时间都不推进，木桶动作仍保留（`inventory_pause`、`dialogue_pause`）。静态调用链为 `Loop:SetInventoryOpen/SetElderOpen` 更新 pause reason，`Game:Sync` 镜像到 Runtime.paused，`Runtime:Update` 在暂停时返回。
- 透镜关闭契约静态核对通过：[Loop:SyncScope](../../scripts/Gameplay/Loop.lua#L1045) 忽略 setter 的返回真假值，随后以 `IsScopeEnabled()` 回读与期望状态比较；[Runtime:SetScopeEnabled](../../scripts/Ocean/SeaRuntime.lua#L402) 关闭成功后返回修改后的 `false`。场景停止走 `DisableScope` 后同样通过回读验收。没有发现把成功的 false 判成失败的当前调用点。
- 唯一 World/System 的代码结构一致：[Game.New/GetWorld](../../scripts/Game/Game.lua#L18) 将一份 Gameplay frame System 幂等注册到当前 Runtime World；`World:AddSystem` 按 system 对象去重（[World.lua](../../scripts/Game/World.lua#L27)）。Gameplay 帧更新通过该 World 的 `frame` cadence 调度，Ocean `Runtime:Update` 再在同一 `self.world` 上执行 simulation cadence（[SeaRuntime.lua](../../scripts/Ocean/SeaRuntime.lua#L427)）。静态未见 Integration 再直接调用 `Loop:Update` 或创建第二个 World；本轮没有把架构套件当成运行证据。
- Bridge 准备回执未再直接读 `runtime.world`：当前 [Bridge.lua](../../scripts/Integration/Bridge.lua#L45) 使用公开 `GetFishingGeneration()` 作回执身份，A Runtime 在初始化和普通鱼刷新时递增该代次（[SeaRuntime.lua](../../scripts/Ocean/SeaRuntime.lua#L20)、[SeaRuntime.lua](../../scripts/Ocean/SeaRuntime.lua#L91)）。但接口矩阵 #10 指定的准备路径通过 `bridge.game:GetWorld()` 获取当前 World 的 façade 夹具尚未执行；当前准备回执实际使用 `GetFishingGeneration()`，不是 `game:GetWorld()`。这不是已证实的当前功能错误，记录为接口矩阵动态验收待证。没有运行原生窗口或真实云，也没有据静态检查声称其通过。
