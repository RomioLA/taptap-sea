# 任务 B：完整捕鱼流程、收费与满舱接收

你在电脑 B 的复制项目执行本任务。先阅读本目录 `共同接口与边界.md`，再阅读项目 `AGENTS.md`。A 同时开发海洋捕获锁定接口和大鱼捕食冷却，本任务负责主要的玩家流程。

## 目标

把正式场景中的捕鱼操作做成可操作、可取消、按新版收费的完整动作，补齐满舱接收流程。玩家可以选择合法网心并确认；约 0.5 秒网落水时选择最近 0/1 条鱼并锁定；共 4 秒完成动作，按该结果结算。起手至少 40 体力，成功收费 40，空网、失败、取消和未完成的夜尽中断均为 0。

## 捕鱼流程

1. 把选择网心、确认、进度、取消和结果接到当前正式 `Integration.Scene`，兼容鼠标和触摸。使用现有 UI 体系；按项目引擎指南查文档/示例。新增键位不得写成策划定稿，可先通过明确的 UI 操作完成流程。
2. 确认时校验网心和起手体力，不要求背包有空位，不提前选择或保留一条鱼。设置网心后只能开始一个捕鱼事务。
3. 起手后约 0.5 秒查询网内最近有效鱼，并立即用共同接口加锁；合法空网也锁定为明确的空结果。后续不重新选鱼，不由调用者伪造 catchCount 或鱼 ID。加锁失败按免费失败处理，不擅自补选另一条鱼。
4. 4 秒时按已锁定结果完成。重复调用、连续点击、同 token 重放、异常重试不能重复扣费、发放或移除鱼；保留并扩展现有回滚机制。旧的直接 CompleteFishing 路径不能绕过动作阶段。
5. 捕鱼中世界继续运行，船不能移动，背包不能打开；禁止再次捕鱼及与该事务冲突的交互。保留合法取消和现有手动暂停。暂停时停止动作进度；恢复后继续。不能为了阻止移动而暂停整个世界。
6. 使用唯一 Gameplay 昼夜时钟的有效推进时间，保持既有海洋模拟与帧调度职责；测试 0.5 秒/4 秒边界和大 dt，不让整帧跨越造成提前选鱼或重复结束。同一帧遇到夜尽或世代变更，先终止未完成行动、释放锁，再进入既有返港/结算流程，不新造强返路线或改罚则。
7. 取消或中断免费、解除锁，已流逝时间不退回；异常操作及非法网心不能消耗体力或留下挂起事务。取消/Reset/换日/停止场景必须处理持有的 runtime 和 token，防止锁遗漏。

## 满舱接收

- 满舱仍能抛网；空网完成后无需腾格。
- 成功收获放不下时保留真实待接收收获，打开船舱并解释空间不足；腾出足够格子前不能关闭整个船舱，物品子菜单仍可返回。
- 允许按现有物品规则使用、交给老人或丢弃已有普通物品。老人不在时给出解释，不编造远程交付；已有关键物品保护继续生效。
- 不采用“替换新鱼/换格”流程，不静默丢弃收获。待接收普通物品支持要求足够格子的检查，但本任务只把普通捕鱼接入此机制，不新增木桶、宝藏或剧情。
- 已完成收获与未完成捕鱼区分清楚：等待腾格时不得再次扣费或重新抓鱼，夜尽不能把已经完成的收获当成未完成动作丢掉。成功结果何时转成待接收物品可由技术层决定，必须用异常与重试测试证明体力、库存、世界实体和待接收记录一致。
- 普通收获、背包消费/丢弃和回滚要有明确归属；保持既有非堆叠容量、日结存档约定，不临时增加未经核对的存档字段或修改数据 Schema。
