# Circle 1 A3 稳定性与生态体验回归

本报告记录 task 4（长航线与重建稳定性）和 task 6（正常种群的捕鱼、提示与透镜组合）。验证使用项目现有 Lupa/Lua 5.4 运行器，执行真实 Lua 海洋 Runtime 与航行逻辑。它不是原生 UrhoX/Maker 试玩，也没有复制玩家 UI。

完整逐项结果见 [results.json](results.json)，对应 Lua 用例为 `scripts/tests/Circle1A3StabilityTests.lua` 与 `scripts/tests/Circle1A3ExperienceTests.lua`。首次运行及水域裁剪复核前的记录分别保存在 [results-first-attempt.json](results-first-attempt.json) 和 [results-before-seadraw-water-check.json](results-before-seadraw-water-check.json)。本目录的 preview status 记录显示本机 preview 为 stopped；没有启动或刷新它。

## 正常种群长航线

稳定性长测采用鱼群正常密度目标（沙丁鱼 20、金枪鱼 4），未提高数量上限，也没有自然补鱼或无位置 fallback。每个 seed 从 `(0,0)` 初始化，沿 `{35,5} → {60,25} → {85,25} → {180,0} → {-180,0} → {0,0}` 往返，经过固定漂流木桶航路；每组模拟约 122.3 秒、2,446 次固定步更新。三个 seed 均访问 16 个区域，每个区域最多生成一次；已捕获鱼在同日回访后仍保持移除。

| Seed | 初始沙丁鱼 / 金枪鱼 | 航线峰值鱼数 | 同日访问区域 |
| --- | ---: | ---: | ---: |
| 271828 | 57 / 6 | 106 | 16 |
| 314159 | 59 / 5 | 111 | 16 |
| 161803 | 57 / 4 | 108 | 16 |

航线扩展到新区域时鱼数随正常区域生成增加；这些数字不是密度上限或补充机制。另一次换日回归确认普通鱼、临时诱饵和定时透镜揭示被清除，而固定木桶保持相同实体、ID 与代次；新日初始化了 64 条普通鱼。

默认 seed `271828` 的 task 6 体验航线单独从 `(0,0)` 起步，绕桶到 `{35,5} → {60,25} → {85,25}`，随后返回 `{35,5} → {0,0}`。桶路体验采样后，以默认 Level 1 船速沿北向 `(0,1)` 连续航行 120 秒（2,400 次、每步 0.05 秒）。两次新建 Runtime 的该完整场景产生相同 digest。起始默认种群有 57 条沙丁鱼与 6 条金枪鱼；完成扩区后世界中记录 169 条沙丁鱼与 30 条金枪鱼。目标密度配置仍为 20/4。

桶路上没有在船附近观察到金枪鱼或水花（当地活跃自然金枪鱼为 0），与金枪鱼距日出发点至少 200 米的生成限制相符。北向长航阶段观察到最多 5 条附近自然金枪鱼、12 个真实水花来源；480 个每 0.25 秒采样帧中，480 帧有海鸟来源、386 帧有水花来源。此路线没有调用 `spawnFish` 或创建信号夹具。

## 同一条天然鱼上的提示、捕鱼查询与透镜

在固定桶附近，正常种群中的沙丁鱼 `sea-61` 是真实海鸟提示来源。捕鱼查询以这条鱼当前的世界坐标作为合法查询中心，距离船 11.55 米，`selectFishingTarget` 选中了同一条 `sea-61`。测试随后通过真实 Movement/Runtime 更新逐帧朝鱼转向：15 个 0.05 秒更新后船移动 3.53 米，透镜使用当前船实体和朝向显示这条鱼。该时刻没有全图水下调试显示或定时揭示。这个查询中心是测试提供的天然鱼坐标，不代表真人输入或原生抛网操作。

## SeaDraw 水域内水花坐标

最初的屏幕矩形计数把地平线上方的水花也算入，不能据此声称水域内可见。复核后按 [SeaDraw.lua](../../../scripts/Ocean/SeaDraw.lua) 的 splash margin `4 * pixelsPerUnit + 3`（当前 viewport 为 1920×1080、viewHeight 为 45 米，即 99 px）应用 `onScreen` 条件，再应用水域 scissor（`horizonY = 1080 * 0.32 = 345.6`）。修正后的重复路线记录到 82 帧水花中心位于水域且满足 SeaDraw margin 相交条件；其中 48 帧的完整 99 px splash margin 都在屏幕及水域内。

可复现的完整水域样本：北向路线第 765 步、模拟时间 71.35 秒；水花源 `sea-92`；船位置 `(-0.58646, 228.49018)`，水花世界位置 `(40.28355, 227.59922)`，投影位置 `(1652.88, 489.18)`。此帧中心在 horizon 以下，完整 splash margin 也处于水域和屏幕边界内。坐标来自 Lua `Movement:WorldToScreen`，是离线投影/来源证据，不是实际屏幕截图或原生绘制验收。

## 暂停、捕食夹具与重建

正常生态体验路线没有注入鱼。稳定性模块中另有清楚隔离的控制夹具，专门验证依赖组合与清理行为：在 `initializeRegions=false` 的独立 Runtime 中，用实际 `spawnFish` 放置沙丁鱼和金枪鱼，再调用真实 `spawnDroppedItem` 建立沙丁鱼诱饵。真实 Fish 行为捕食后记录到配置的 5 秒冷却；在暂停前读取的剩余时间为约 3.95 秒。暂停两秒期间船、鱼、世界时钟、诱饵寿命、冷却截止值、海鸟位置与水花/信号计时均未推进；恢复后重新推进。该控制夹具证明规则组合与计时，不冒充自然种群路线上的真人遭遇。

取消捕鱼锁、捕获移除、实际 `_tryEat` 捕食、Reset 后提示清理均通过。重建回归重复 5 次：每个旧 World 的实体数组和系统注册清空，scope 船引用及信号 World 引用解除；继续显式更新外部仍持有的旧 World 时，共享 Gameplay 计数器没有增加；每个新 World 只注册 EntityState、SurfaceSignals 和 Gameplay frame System 各一次。速度/碰撞回归对 Level 1/2/3 分别验证真实 6/8/10 m/s 行进、转向和扫掠岛屿碰撞。

## 首轮问题与边界观察

首轮有三处测试假设需要修正：

- 多 seed 用例错误要求自定义 `daySeed` 同时反映在 `World.daySeed` 字段。回归改为直接记录实际生成策略收到的 Runtime seed，并保留 World 字段观测，不把镜像字段当作航行正确性的先决条件。
- 鱼刚生成后只更新一次就检查海鸟，早于信号轮询周期。用例等待轮询完成后再断言。
- 固定时长直航后要求指定鱼必定在透镜锥内不稳定。改为逐帧沿同一条真实候选鱼调整 Movement，并以实际进入移动透镜锥作为通过条件。

父任务复核水花证据后，又将屏幕矩形判断改为 SeaDraw margin 与水域裁剪判断；上述 82/48 帧和完整水域坐标均来自该修正后的复测。

另外记录到一项字段镜像差异：`Runtime.New({daySeed=314159})` 和 `Runtime.New({daySeed=161803})` 的普通生成策略分别收到对应 Runtime seed，航线回归均通过；但 `world.daySeed` 仍为 World 默认值 `271828`。本次未修改 Runtime 正式代码，保留此观察供其 owner 判断。

本报告和全部结果均属纯 Lua/Lupa 航行与回归证据。原生预览当时已停止，未启动；原生控制、UI、实际 Maker 画面和人类玩家体验均未测试。
